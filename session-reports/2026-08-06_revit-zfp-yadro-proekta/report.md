## Кратко

Пересмотрен подход к разработке Revit-семейств. Разобраны три конкурирующих
курса, выбран гибрид: методика Claude Design (паспорт + обмер STL →
параметрический эталон) + сборка прямым Revit API через штатный MCP + гейт
числа плюс рендеры.

Собран скелет семейства ZFP (канальный вентилятор ZILON): каркас опорных
плоскостей с EQ, 18 ADSK shared, два связанных воздушных коннектора на
плоскостях фланцев, каталог 19 типоразмеров. Гейт 180 проверок, 0 провалов.
Геометрии нет намеренно — форма приходит из Claude Design.

## Что из этого переносимо на другие проекты

- **Канал в Revit без стейджа:** код лежит файлами в проекте, внутрь Revit
  инлайном уходит ASCII-загрузчик, читающий модуль через .NET как UTF-8.
  Кириллица инлайном приходит искажённой даже с coding-строкой. Записано в
  память `revit_routes_channel_traps`.
- **Три записанных «факта» не подтвердились замером** (void не режет,
  sweep/blend заглушки, BuiltInParameterGroup рабочий). Урок: перед тем как
  строить архитектуру вокруг ограничения, ограничение надо перепроверить.
- **Гейт проверяет ровно то, что ему велели.** Зелёный вердикт при неполном
  наборе проверок ничего не доказывает — поймано на типах ссылок опорных
  плоскостей: положения верные, Is Reference у всех неверный, вердикт PASS.
- **Единое ядро для нескольких агентов:** источник один (`Claude/CLAUDE.md`),
  из него генерируется `AGENTS.md` — Claude и Codex стартуют с одного текста.
  Второго статуса/журнала/фактов не заводить; рабочий ledger агента — инструмент
  внутри своей папки прогона, выводы обязаны дойти до общего журнала.
