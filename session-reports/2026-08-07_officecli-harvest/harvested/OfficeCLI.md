## Зачем смотрели

Пользователь применял инструмент и попросил оценку. Проверялось на фоне нашего
накопленного провала правки docx ([[reference_docx_editing_failures]]).

## Оценка

**Подходит? Под условием.**

### Сильные стороны — закрывает наши задокументированные failure-modes

- `view --screenshot` / `html` / `pdf` — рендер документа в картинку через headless
  browser. Прямо закрывает failure-mode #7 «сдавал не глядя = ложный рапорт» и
  правило владельца «смотреть своими глазами после каждого шага».
- Правка **живого файла** по DOM-пути (`/body/p[3]`, `/Sheet1/B2`) через `set`/`find`
  вместо пересборки с нуля — адресует failure-mode #1 (исчезающая фирменная шапка)
  и #3 (переписывание абзаца целиком затирает табы и подчёркивания полей).
- Трёхуровневая стратегия L1 (read) → L2 (DOM edit) → L3 (raw XML): падение на
  уровень XML доступно, но не является нормой работы.
- Stable ID addressing, `batch --best-effort`, `--json` у всех команд — машинно-читаемо.
- `watch` + `get <file> selected` + `mark`/`get-marks`: пользователь кликает в
  документе, агент читает выделение и оставляет предложения правок на ревью.
- Не требует Office, Python-стека и MCP-сервера; один бинарь на машину.

### По форматам — выигрыш очень разный

**.docx — прорыв.** См. выше: правка живого файла по DOM-пути вместо пересборки плюс
рендер для визуальной сверки закрывают ровно наши failure-modes.

**.xlsx — улучшение, но не революция:** MCP `excel` у нас уже богат (чтение/запись,
формулы, форматирование, merge, `create_pivot_table`, графики, валидация формул).
Реальная дельта OfficeCLI:

- **Селекторы с булевой логикой** — `cell[value>5000 or value<100]`,
  `cell[(type=Number or type=Date) and value>0]`, `:has(formula)`, `:empty`,
  `:contains("…")`, и выборка строк по имени колонки: `Sheet1!row[Salary>5000]`.
  Причём селекторы работают не только в `query`, но и в `set`/`remove` — массовая
  правка по условию. Прямо ложится на спецификации и ВОР: «все позиции без цены»,
  «где вместо числа осталась формула», «где количество пустое».
- **Сортировка, которая не портит лист**: sidecar-метаданные (гиперссылки,
  комментарии, условное форматирование, drawings) едут за строками, а диапазоны
  с объединёнными ячейками или формулами она **отказывается** сортировать. Merged
  cells — наша постоянная боль в сметах.
- **Сводные таблицы** с полной схемой (`rows`/`cols`/`values`/`filters`/`aggregate`/
  `showDataAs`/`grandTotals`/`subtotals`/`sort`, автогруппировка дат) — заметно
  подробнее, чем `openpyxl` умеет сам.
- `calc.mode=manual`, `calc.refMode=r1c1`; `batch --best-effort` за один цикл сохранения.
- `view --screenshot` работает и для xlsx — визуальная проверка вёрстки таблицы.

Ограничения именно по Excel, которые надо знать заранее:

- `find` в Excel — **только find + replace, без форматирования** (в Word форматирование
  по найденному есть, в Excel нет).
- **`.xlsx` не отдаёт `data-path`**, поэтому `mark`/`selection` на нём всегда
  `stale=true` (в самом SKILL.md помечено как «v2 candidate»). Сценарий «пользователь
  кликнул ячейку — агент прочитал выделение» для Excel **не работает**, хотя для
  docx/pptx работает.
- Специализированные под-скиллы (`financial-model`, `data-dashboard`) заточены под
  западные бизнес-формы, не под сметы и ВОР по ГЭСН/ФЕР — наши формы всё равно
  остаются на нашем слое.

**.pptx — закрывает пустое место.** MCP для PowerPoint у нас нет вообще, только
`anthropic-skills:pptx`. OfficeCLI даёт shapes/pictures/tables/charts/connectors/groups,
адресацию по имени (`shape[@name=Title 1]`), рендер слайда в SVG/PNG и click-to-select
в браузере. Для КП и презентаций заказчику это самый большой прирост из трёх форматов.

### Слабые стороны и риски

1. **Установщик fail-open по чек-сумме.** `install.ps1` сверяет SHA256SUMS
   (`Get-FileHash`, при несовпадении прерывает — хорошо), но при недоступности файла
   сумм печатает «Checksum file not available, skipping verification» и **продолжает
   установку**. Проверки Authenticode нет вообще. Наш стандарт приёмки клиента —
   SHA-256 + валидная подпись, это ниже планки.
2. **Автоматически прописывается в чужие агенты.** `install.ps1` при первой установке
   раскладывает свой скилл в `~/.claude`, `~/.agents` (Codex), `~/.hermes` и другие
   обнаруженные каталоги, а также **правит пользовательский PATH**. Для базы это
   вмешательство в управляемую поверхность: компонент появляется в `~/.claude/skills/`
   мимо `$sync-base` и на всех машинах расползается неконтролируемо.
3. **Рекламируемый способ подключения — вектор исполнения инструкций из сети.**
   «Киньте агенту `curl -fsSL https://officecli.ai/SKILL.md`» означает, что агент
   читает живой эндпоинт и по нему сам ставит бинарь. Содержимое домена не
   версионировано и может измениться. В репозитории тот же SKILL.md (291 строка)
   версионирован и ревьюим — читать надо его.
4. **Молодой проект.** 5 месяцев, при этом 26k звёзд — рост нехарактерно быстрый.
   Контраргументы в пользу зрелости: 30 релизов, свежие коммиты, реальные загрузки
   (win-x64 10 311, linux-x64 9 918), в установщике есть осознанная защита от
   stale-CDN (immutable versioned path вместо `/releases/latest/download/` из-за
   4-часового кеша и риска самосогласованного устаревшего SHA256SUMS) — так пишут
   инженеры, а не маркетинг. SECURITY.md есть, приватный канал раскрытия заявлен.
5. **Чужой стек.** C#/.NET против нашего Python + PowerShell: при баге внутри
   отладка дорогая, форк нереалистичен. Single binary этот риск частично снимает.

### Решение

**Держим как кандидата с ручным вводом в эксплуатацию:**

- бинарь брать **из GitHub Releases** и сверять с `SHA256SUMS` вручную, а не
  `install.sh`/`install.ps1` и не `irm | iex`;
- **не запускать `officecli install`** — он трогает PATH и чужие агентские каталоги;
- инструкцию `curl -fsSL https://officecli.ai/SKILL.md` в чат агента не подавать;
  при заведении в базу писать свою обёртку-SKILL.md на основе версионированного
  файла из репозитория;
- первый прогон — в `~/.claude/_sandbox/` на копиях реальных бланков, с обязательной
  проверкой того самого сценария, где мы горели: правка бланка с плавающим логотипом
  и подчёркиваниями полей + `view --screenshot` для визуальной сверки.

Адаптация в базу — отдельный шаг с согласием владельца, не следствие этой оценки.
