# Методичка LLM-base

> Актуально для Claude, Codex и OpenCode. Источник обновляет только hub; рабочие
> устройства получают проверенный пакет односторонне.

## 1. Что устанавливает база

База состоит из четырёх разных слоёв:

1. компактное vendor-neutral ядро общих правил;
2. тонкий нативный слой конкретного клиента;
3. явно активированные агенты и навыки;
4. каталог остальных компонентов, который не попадает в стартовый контекст.

По умолчанию активен только read-only `auditor`, навыков нет. Это не удаляет
проектные наработки: они остаются в исходном каталоге hub и подключаются в
пакет только через `base-manifest.json`.

| Клиент | Основные управляемые пути |
|---|---|
| Claude | `~/.claude/CLAUDE.md`, `~/.claude/core/`, `~/.claude/agents/` |
| Codex | `~/.codex/AGENTS.md`, `~/.codex/agents/` |
| OpenCode | `~/.config/opencode/AGENTS.md`, `opencode.json`, `agents/` |

OpenCode — самостоятельный клиент, а не модель. Провайдер и модель выбирает
пользователь в OpenCode; база их не фиксирует и не переключает на платный
fallback.

## 2. Роли и односторонний sync

Маркер `.developer-marker` в корне build-репозитория определяет роль:

| Роль | Получение main | Публикация |
|---|---|---|
| hub | pull | разрешена после проверки |
| consumer | pull | отключена |

На consumer `origin` push URL заменён на `NO_PUSH_CONSUMER`. SessionEnd является
локальным no-op. Consumer не отправляет:

- историю и отчёты сессий;
- телеметрию;
- предложения и локальные правила;
- документы, auth-файлы и переменные окружения.

Старый обратный канал выведен из эксплуатации. Его репозиторий следует оставить
архивным read-only, а прежний write-token отозвать.

## 3. Автоматизация и граница миграции

Hub/legacy-конфигурация Claude содержит только два sync-hook:

- `SessionStart` → `auto-pull.ps1`;
- `SessionEnd` → `auto-push.ps1`, который публикует только на hub.

Новый target-bound render сам по себе не означает настроенный updater.
Обновление consumer home выполняется только утверждённым Foundation package.
Пока immutable package отсутствует, `/sync-base` должен ограничиться pull,
verify и doctor, вернуть `BLOCKED_APPROVED_FOUNDATION_SOURCE` и не писать raw
render поверх пользовательских файлов.

База не навязывает:

- `effortLevel` или reasoning tier;
- модель;
- плагины;
- prompt hooks;
- PostToolUse telemetry;
- автоматический fan-out, reviewer или MCP-вызов.

При первой миграции прежние принудительные expensive-настройки удаляются один
раз. После этого пользователь может задать личные model/reasoning/plugins, и
общая база их не перезапишет.

## 4. Правила экономии токенов

- Приветствие и простой вопрос: ноль инструментов, агентов и ревьюеров.
- Для задачи выбирается минимальная локальная проверка.
- Большой файл, каталог навыков или история не читаются заранее.
- Независимый агент подключается только для существенного результата, явного
  запроса или реальной независимой подзадачи.
- Смена темы или резко разросшийся контекст — новый чат с коротким handoff.
- Не переносить в другой LLM транскрипт целиком; передавать цель, ограничения,
  источники и критерий готовности.

Бюджет проверяется командой:

```powershell
python "$Repo\scripts\base_cli.py" verify
```

Фактический JSONL можно проверить без раскрытия prompt:

```powershell
python "$Repo\scripts\base_cli.py" audit-transcript <session.jsonl>
```

Отчёт показывает только счётчики, распределения и хешированный fingerprint
максимального запроса.

## 5. Агенты, навыки и инструменты

Каталог не равен активации. Наличие компонента в исходном репозитории не должно
делать его видимым каждой модели.

Активация меняется в `base-manifest.json` отдельно для `claude`, `codex` и
`opencode`. После изменения hub выполняет:

```powershell
python .\scripts\base_cli.py verify
python .\scripts\base_cli.py render --target <claude|codex|opencode> --output <fake-home>
python .\scripts\base_cli.py doctor --target <target> --home <fake-home>
```

MCP и внешние приложения подключаются под конкретную задачу. Их отсутствие не
должно запускать автоматическую установку, вход в аккаунт или замену модели.

## 6. Команда `/sync-base`

Команда:

1. определяет hub/consumer;
2. на consumer форсирует no-push remote;
3. подтягивает `origin/main`;
4. запускает `base_cli.py verify`;
5. делает doctor уже установленных target;
6. применяет только утверждённый Foundation package, иначе возвращает
   `BLOCKED_APPROVED_FOUNDATION_SOURCE`.

Consumer drift не публикуется. При локальных коммитах или конфликте команда
останавливается и просит отдельное решение; destructive reset автоматически не
выполняется.

## 7. Приватность и блокировки провайдера

- Русский язык документа сам по себе не является основанием считать работу
  нарушением; ограничения конкретного провайдера проверяются отдельно.
- Местоположение, способ регистрации, Usage Policy и необычная активность могут
  влиять на доступ независимо от базы.
- Не использовать bypass разрешений и offensive/security automation по
  умолчанию.
- Не вставлять JWT/PAT/API-key в запросы и логи.
- Не отправлять клиентский документ в облачный OCR/парсер без явного согласия
  на конкретный сервис.
- OpenCode сохраняет политику выбранного провайдера: смена оболочки не обходит
  условия OpenAI, Anthropic или другого поставщика.

## 8. Если что-то не работает

| Симптом | Проверка |
|---|---|
| Каждый короткий запрос слишком дорог | новый чат; проверить startup budget, личный reasoning и активные плагины |
| Consumer пытается push | `git remote get-url --push origin` должен вернуть `NO_PUSH_CONSUMER` |
| Компонент не появился | проверить `active_agents` / `active_skills`, затем render + doctor |
| OpenCode использует Claude-совместимость | запускать через `opencode-base.ps1` и проверить три disable-флага |
| Аккаунт Claude on hold | подать Request a review; не гадать о точной причине без ответа Safeguards |
| Проверка прошла только на fake-home | это synthetic PASS, не полная приёмка сотрудника |
